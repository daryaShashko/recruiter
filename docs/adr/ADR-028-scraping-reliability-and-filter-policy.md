# ADR-028: Надёжность сбора вакансий и политика фильтрации

**Status:** proposed
**Date:** 2026-11-16
**Consulted:** AGENTS.md, ADR-012, ADR-020, ADR-024

## Контекст

Анализ логов GitHub Actions (19.10–15.11), кода скрапера и живой ноды n8n.
Пометки: **[код]** проверено по коду, **[live]** проверено живым запросом 2026-11-16, **[логи]** взято из логов Actions и повторно не проверялось.

- В n8n уходит 270–295 вакансий в сутки (в октябре 50–62; рост с 4.11 за счёт SwissDevJobs/TheHub и с 8.11 за счёт ATS). [логи]
- JustJoin: API игнорирует `perPage=100` и отдаёт по 10. [live] Смещения считаются как `(page−1)×100`, `totalItems/100` даёт 4 страницы. [код] Читается 40 из ~328 вакансий (12%). [код + live]
  Ответ содержит `meta.next.cursor`, это числовое смещение (0 → 10 → 20), страницы не пересекаются. [live]
- `passesTitleFilter` ([global-filter.ts](../../scraper/src/utils/global-filter.ts)) отбрасывает заголовки без senior/lead/staff/principal/architect/head of/founding. [код] Отброшенные не попадают в статистику. [код] У Linear на борде 33 вакансии, до полного фильтра доходят 7. [логи]
  Дальше действует фильтр по JS-сигналам (`no-js-signal`), он тоже может отсечь Product Engineer без стека в описании. [код]
- Возрастной фильтр (`maxAgeDays: 60`) единый для всех источников. [код] Режет открытые ATS-вакансии: Cloudflare 134 из 274, Adyen 71 из 121, Intercom 44 из 64 (лог 15.11). [логи]
- Ashby не запрашивает `includeCompensation` и не передаёт salary; `company` = slug. [код] Lever тоже ставит `company: slug`. [код] Greenhouse, Recruitee, Personio берут название из данных, если оно есть. [код]
- Зарплатные пороги расходятся: профиль 22 000 B2B / 28 000 UoP, код `Math.max(23000, …)` и 27 000. [код]
  `Math.max(23000, …)` стоит в двух местах: [scoring.ts:666](../../n8n/evaluator/scoring.ts) и [notion-profile.ts:494](../../n8n/evaluator/notion-profile.ts). [код]
- Правило «зарплата не указана и компания не Tier-1 → score 0» применяется после вызова LLM, вопреки профилю. Tier-1 сопоставляется по подстроке (Metalab → meta, Uberall → uber). [код]
- Notion считается единым источником, но правка 14.11 в него не попала; `notion:sync` 15.11 вернул старый текст. Причина не установлена (сбой записи, перезапись или ручная правка). [логи]
- LLM-слой: ретраев на 429 нет, роутер перебирает провайдеров и бросает общую ошибку. [код] Любая ошибка даёт score 0. [код]
  Метка `Pipeline: LLM Error` ставится только если текст ошибки содержит «ollama». С текущими провайдерами почти все ошибки получают `Pipeline: Parse Error`. [код]
  Дедуп работает по Evaluation Log: нода `Notion: Find Existing URL` запрашивает ту же базу, что и `Notion: Log to Eval Log`. [live]
  `Code: Check Duplicate` пропускает записи со Score 0/null и переоценивает их. [live] Значит, ошибка LLM дедуп **не блокирует**, но каждый настоящий отказ (score 0) переоценивается при каждом запуске и тратит токены.
- Drift-check сравнивает одну строку-сводку, а не порядок провайдеров, модели и ретраи. [код] Сейчас в живой ноде нет `$env` и литералов провайдеров, таймауты не заданы. [live]

## Решение

1. **JustJoin.** Листать по `meta.next.cursor` до `null` или до вакансий старше порога возраста; потолок страниц как защита (при 10 на странице потолок 30 страниц даёт 300 вакансий, потолок надо поднять минимум до 50).
2. **Воронка.** Счётчики на каждом этапе и в каждом источнике (собрано → отброшено до фильтра: заголовок/isListed/невалидные → прошло фильтр → отправлено). Печатать в лог и передавать в `meta.stats` вебхука.
3. **Заголовочный гейт.** Убрать требование senior-слова. Оставить отказ для junior/intern/trainee. Добавить список семейств ролей, не подходящих профилю (support, sales, SRE, DevOps, QA, data, mobile и т.п.; точный список утверждается в отдельной задаче и хранится в `config.ts`). Уровень оценивает LLM по описанию. Проверить, что фильтр `no-js-signal` не отсекает целевые роли без стека в описании.
4. **Возраст.** Для ATS-источников порог 180 дней (параметр конфигурации), для JustJoin/NoFluffJobs/агрегаторов 60. Перед включением проверить, что дедуп не пропустит давно известные вакансии как новые.
5. **Ashby.** `includeCompensation=true`, разбор compensation в `salary`; таблица slug → название компании в конфигурации для Ashby и Lever; Greenhouse проверить на реальных данных.
6. **Зарплатная политика.** B2B 24 000 PLN net+VAT, UoP 27 000 PLN gross. Нераскрытая зарплата не причина отказа, ставится пометка в карточке. Правило Tier-1 и оба `Math.max(23000, …)` удалить.
   Значения хранить в Notion. Курсы валют вынести из `CURRENCY_RATES_TO_PLN` в одно место с датой актуальности. Валютные эквиваленты в профиле пересчитать из PLN и курсов.
   Изменение требует: правки в Notion и `npm run notion:sync`, обновления `gold_dataset.yaml`/`smoke_dataset.yaml`, `npm run eval:smoke`, `cd n8n && npm run build`, `python3 scripts/patch-n8n-hitl-review.py`.
7. **LLM-слой.** Ретраи с экспоненциальной паузой на 429/5xx. Ошибка не считается оценкой. Исправить определение метки: различимые метки для квоты, ошибки провайдера и разбора (сейчас проверка только на «ollama»). Счётчик ошибок в дайджесте.
7а. Переоценка отказов. Code: Check Duplicate не пропускает записи со Score 0 как «неизвестные». Ошибки (квота, провайдер, разбор) пишутся в Eval Log отдельным статусом без score 0 и переоцениваются; настоящие отказы дедуплицируются как обычные. Перед включением измерить число повторных оценок в сутки.
8. **Drift-check.** Сравнивать хеш кода роутера и разобранные параметры (провайдеры, модели, ретраи, таймауты). Покрыть офлайн-тестом на фикстуре.
9. **Выкатка.** Сначала п.7 вместе с п.6 (иначе правило Tier-1 продолжит давать нули) и п.2, затем п.3–5, п.1 последним. В первый день после п.1 и п.3 ожидается всплеск объёма; перед п.3 и п.4 задать дневной лимит вызовов LLM.

Отложено: судьба SwissDevJobs, TheHub, Adzuna (решение по данным за две недели: доля score ≥ 50 и токены на одну принятую вакансию по источникам); новые источники (Himalayas, 4dayweek, RemoteOK, Jobicy, VC-борды); гигиена списка ATS: `grecotel`, `eurobank` (не IT), `adyen`, `n26`, `monzo`, `wise`, `trivago` дают 0 вакансий после фильтра каждый день. Токены на них не тратятся (их отсекает скрапер), но запросы и время да. Решение по ним можно принять позже.

## Альтернативы

- Оставить senior-гейт: отклонено, теряет целевые роли и не виден в метриках.
- Убрать гейт полностью: отклонено, в LLM пойдут support, sales, SRE.
- Оставить правило Tier-1: отклонено, режет Cloudflare, Grafana, HelloFresh и ломается на подстроках.
- Удалить SwissDevJobs/TheHub сразу: отложено, нет данных по их вкладу после LLM.

## Последствия

Плюсы: видимая воронка, больше целевых вакансий, нет тихих потерь, один источник истины для порогов.
Минусы: рост нагрузки на LLM (оценка не сделана, измеряется счётчиками из п.2); нужны тесты на фикстурах (Ashby с compensation, JustJoin с курсором, drift-check).

## Проверка

- Число вызовов LLM в сутки до и после п.7/7а (ожидается резкое падение за счёт прекращения повторной оценки отказов).
- Счётчики воронки из п.2 печатаются по всем источникам.
- В Eval Log одна вакансия не появляется чаще одного раза в сутки.
- Raw JustJoin равен `totalItems` (или числу вакансий моложе порога).
- Linear «Product Engineer» доходит до LLM; строка salary из Ashby корректно разбирается функцией `extractMaxMonthlyPln` (годовая сумма, суффикс K, валюта), и без пометки UoP применяется порог B2B.
- Ни один запуск не даёт score 0 с причиной ошибки LLM.
- Перед включением п.4 проведён сухой прогон с порогом 180 дней для ATS с фиксацией числа вакансий, проходящих фильтр.
- После `npm run notion:sync` в `.notion-snapshot.json` зафиксированы значения порогов 24000 (B2B) и 27000 (UoP).
- Повторный запуск не переоценивает вакансии, уже получившие настоящий отказ.
