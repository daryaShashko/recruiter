## 3. Обнаруженные проблемы

### INCIDENT-001: NoFluffJobs — переход на Angular SSR (критический)

**Дата обнаружения:** 2026-05 (при разработке P1-11)  
**Серьёзность:** Критический — полная потеря данных с источника NFJ  
**Симптом:** NoFluffJobs возвращал 0 вакансий в runs 1–3.  
**Причина:** NFJ отказался от POST XHR `/api/search/posting` и перешёл на Angular SSR.
Данные о вакансиях теперь встроены в HTML-страницу в тег
`<script id="serverApp-state">` под ключом `STORE_KEY`.  
**Статус:** Исправлен (P1-11 — SSR-экстрактор реализован).  
**Ссылка:** `scraper/src/scrapers/nofluffjobs.ts` → функция `extractSsrPostings()`.

---

### ISSUE-001: JustJoin — прямая навигация не тригерит API (известное ограничение)

**Серьёзность:** Средний — требует специфического flow навигации  
**Описание:** Прямой переход на `justjoin.it/job-offers/all-locations/javascript`
использует SSR и не вызывает `candidate-api/offers`. API срабатывает только
при клике на категорию внутри SPA.  
**Решение:** Скрапер открывает главную страницу → кликает на ссылку JavaScript-категории.
Если клик не работает — fallback: прямая навигация (менее надёжно).  
**Статус:** Обходной путь реализован, задокументирован в коде.

---

### ISSUE-002: JustJoin — id содержит дубликаты для одной вакансии в разных локациях

**Серьёзность:** Низкий — уже деплой  
**Описание:** JustJoin иногда возвращает одну вакансию с двумя разными `slug`-ами
(например, с суффиксом хеша `_3f0c25e1`). Это приводит к двум записям в dry-run.  
**Пример из dry-run:**
```json
{"id": "justjoin_chabre-it-services-sp-z-o-o-tech-lead-node-js-react--warszawa-javascript"}
{"id": "justjoin_chabre-it-services-sp-z-o-o-tech-lead-node-js-react--warszawa-javascript-3f0c25e1"}
```
**Решение:** Deduplication в `index.ts` по `id` (Set) убирает дубли с одинаковым `url`,
но не дубли с разными `slug`-ами при одинаковом контенте.  
**Статус:** Частично обработан. Полная дедупликация — post-POC задача IMPROVE-X.

---

### ISSUE-003: Нет оповещения при 0 вакансиях (open)

**Серьёзность:** Средний — нет обратной связи о поломке в production  
**Описание:** Если скрапер вернёт 0 вакансий (API сломался), система не пришлёт
никакого сигнала. Данные просто не поступают в n8n.  
**Статус:** Открыт (P6-4 в roadmap).  
**Предлагаемое решение:** GitHub Actions step с `if: steps.scrape.outputs.count == 0` →
Telegram-сообщение с предупреждением.

---

### ISSUE-004: Локальный n8n tunnel сбрасывается при перезапуске (известное)

**Серьёзность:** Средний — требует ручного обновления Secret  
**Описание:** `npx localtunnel --port 5678` генерирует новый URL при каждом перезапуске
(если subdomain занят). GitHub Secret `WEBHOOK_URL` требует ручного обновления.  
**Статус:** Известное ограничение архитектуры (P2-2). Задокументировано в `known_blockers`.

### Вопрос: Система готова к unsupervised режиму?

**Ответ: Условно готова.**

**Что работает без надзора:**
- Ежедневный scrape в 08:00 через GitHub Actions cron.
- Фильтрация по стеку, локации, уровню.
- LLM-оценка и добавление в Notion.
- Deduplication — повторные вакансии не добавляются.

**Что требует ручного вмешательства:**
- При смене API JustJoin или SSR-ключа NFJ — нет автоматического оповещения о поломке.
- При перезапуске n8n (tunnel URL меняется) — нужно обновить `WEBHOOK_URL` в GitHub Secrets.
- Ротация User-Agent не реализована — риск блокировки Cloudflare через 30+ дней.

**Рекомендация:** Запустить в production на 7 дней с ежедневной ручной проверкой.
После внедрения P6-3 (Telegram alert при падении) и P6-4 (alert при 0 вакансиях)
система переходит в fully unsupervised режим.
